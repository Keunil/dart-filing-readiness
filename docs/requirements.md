# 과제 2 요구사항과 수용 기준

기준 문서: 사용자가 제공한 `과제2-설명.html`의 「AI와 함께 만들기: Vibe Coding 웹 애플리케이션」. 제출 기한은 2026년 10월 28일(수) 자정이며 제출 장소는 LearnUs다. 이 문서는 첨부 문서의 과제 조건을 작업 요구사항으로 정리한 것이다.

## 문제 정의

작성자가 경험한 공시 관련 업무에서는 제출 전 문서의 일부 형식·구조와 기재 사항을 반복해서 확인했다. 이 개인 경험에서 점검 후보와 원문 근거를 함께 보여 주는 과제 아이디어를 얻었다. 회사의 공식 조직 정의·인력 운영·전체 업무 절차를 대변하지 않는다.

## 기능 수용 기준

| ID | 기능 | 관찰 가능한 완료 기준 |
|---|---|---|
| F1 | DSD 읽기 | 사용자가 선택한 `.dsd`의 ZIP/XML을 읽고 문서명·회사·코드를 표시한다. 잘못된 파일은 이해 가능한 오류로 안내한다. |
| F2 | 체험 자료 | 실제 고객 자료 없이 가상 DSD를 실행하고 수정 전후의 차이를 볼 수 있다. |
| F3 | 서식 분리 | 연차 `00760/00761`과 분·반기 `90020/90220/90320/90420`를 구분한다. 범위 밖·코드 미확인은 자동 점검을 진행하지 않는다. |
| F4 | 감사인 프로필 | 입력한 이름·식별값·주소·대표자를 기준으로 감사인 관련 항목을 확인한다. 가상 기본값임을 사용자가 알 수 있다. |
| F5 | 상태 구분 | 오류·확인 필요·수동 확인·통과·해당 없음을 별도로 표시한다. 자동 점검의 성공만으로 수동 확인을 통과로 바꾸지 않는다. |
| F6 | 결과 탐색 | 검색·상태 필터를 바꾸면 해당 항목과 건수가 바뀐다. |
| F7 | 원문 근거 | 결과의 근거를 선택하면 관련 원문 위치나 헤더 정보를 확인한다. 원문 값을 임의로 고치지 않는다. |
| F8 | 검토 기록 | 사람이 확인한 표시와 기계의 원래 판정을 구별한다. |
| F9 | 결과 내보내기 | 결과를 CSV 또는 XLSX로 내려받고 항목·상태·근거를 확인한다. |
| F10 | 브라우저 내 처리 | 파일·분석 결과를 서버로 보내지 않으며 `connect-src 'none'` 정책을 적용한다. |
| F11 | 공개 사용성 | 공개 URL에서 로그인·자료 다운로드 없이 체험을 시작하고 모바일에서도 핵심 기능을 사용할 수 있다. |
| F12 | 제출 완성도 | 보고서의 URL·저장소·화면 이미지·AI 사례가 실제 산출물과 일치한다. |

## 평가 비중과 증거

| 평가 항목 | 비중 | 제출 근거 |
|---|---:|---|
| 기본 기능과 실제 작동 | 30% | 공개 체험, 실제 브라우저 기능 확인, 개발자 테스트 |
| 구조와 기능의 적절성 | 20% | 브라우저 처리 구조, 서식별 규칙, 수동 판단 분리 |
| AI 활용 및 개발 과정 | 20% | 요구사항·범위 결정·역할 분담·코드 재사용 기록 |
| 오류 발견·수정 및 문제 해결 | 20% | 실제 관측한 근거 창 스크롤 오류 수정, 내보내기 경계 입력 시험, 감사인 프로필과 합성 체험 구성 |
| 배포와 제출물 완성도 | 10% | 앱·GitHub URL, 보고서와 주요 화면 캡처 |
