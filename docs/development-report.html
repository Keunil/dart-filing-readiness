1. 문제 정의와 개발 목표

공시팀은 제출 전 DSD의 오류를 체크리스트에 따라 수기로 최종 확인한다. 제출이 집중되는 시기에는 점검 업무가 과중해지며, 누락이나 반복적인 재검토가 공시 지연으로 이어질 위험이 있다.

반복적으로 확인하는 항목을 먼저 점검하고 오류 위치를 원문과 연결하여, 담당자가 검토할 부분을 빠르게 찾도록 하는 데 개발 목표를 두었다.

주요 기능구현 내용
DSD 읽기파일 선택과 끌어놓기로 문서를 불러온다.
서식별 점검감사·연결감사·분기·반기 검토보고서에 맞는 규칙을 적용한다.
결과 탐색상태별 필터와 검색으로 확인할 항목을 찾는다.
원문 확인항목별 근거와 문서 내 해당 위치를 함께 보여 준다.
검토·내보내기확인 표시를 남기고 CSV 또는 Excel로 결과를 저장한다.

2. 파일 선택과 점검 시작

감사인 기준을 확인한 뒤 DSD 파일을 선택하거나 화면에 끌어놓으면 점검이 시작된다.

사용 순서

  1. 감사인 명칭·식별값·주소·대표자 기준을 확인한다.
  2. 첨부 ZIP을 풀고 점검할 DSD 파일을 선택한다.
  3. 결과에서 오류 후보와 확인할 항목을 찾는다.
  4. 원문 근거를 검토하고 결과를 내려받는다.

3. 점검 결과와 검토

58개 출력 항목을 상태별로 모아 보여 주고, 검색과 필터로 필요한 결과를 좁힐 수 있다.

상태표시 의미
오류 후보설정한 점검 규칙과 다른 내용이 발견된 항목이다.
확인 필요추가로 원문을 대조할 항목이다.
수동 확인담당자의 검토가 필요한 항목이다.
통과적용한 규칙에서 문제를 찾지 않은 항목이다.
해당 없음현재 문서에 적용되지 않는 항목이다.

검토한 항목에는 ‘직접 확인’을 표시할 수 있다. 결과 파일에는 항목, 판정, 원문 근거와 확인 기록이 함께 포함된다.

4. 원문 확인과 구현 구조

실제 사례에서는 커뮤니케이션 횟수와 기재된 날짜 수의 불일치가 표시되었다. 근거 버튼을 누르면 관련 문단이나 표로 이동하여 내용을 대조할 수 있다.

작동 방식

DSD 선택 → ZIP 내부 XML 읽기 → 문서 구조 파악 → 서식별 규칙 실행 → 결과·원문 위치 표시 → CSV·Excel 내보내기

구성역할
HTML·CSS파일 입력과 점검 결과를 화면에 배치한다.
JavaScript파일 읽기와 점검을 실행하고 검색·필터·내보내기를 처리한다.
브라우저 메모리DSD 원본과 점검 결과를 메모리에 두며, 문서를 비우거나 창을 닫으면 초기화한다.
정적 웹 호스팅브라우저에서 실행할 화면과 프로그램 파일을 제공한다.

5. AI 활용과 문제 해결

Codex와 함께 기존 DSD 읽기·점검 엔진을 재사용하고 브라우저에서 실행하는 정적 웹 앱으로 구조를 정한 뒤, 파일 입력, 결과 탐색, 원문 연결과 내보내기 기능을 구현하였다. 구현 과정에서 발견한 문제를 다음과 같이 수정하였다.

원문 근거 창의 스크롤 오류

원문 위치로 이동할 때 화면 전체가 스크롤되어 제목과 닫기 버튼이 화면 밖으로 밀리는 문제가 발생하였다. 제목과 닫기 버튼이 유지되도록 근거 창의 동작을 재현하고 수정하는 작업을 Codex에 맡겼다. Codex는 원문을 찾는 스크롤이 바깥 창까지 움직이는 것을 확인하고, 원문 패널 안에서만 이동하도록 제안하였다. 내부 스크롤과 창의 초기 위치를 조정한 뒤에는 원문으로 이동해도 제목과 닫기 버튼이 유지되었다.

문서 초기화 후 남는 이전 내용

문서를 비운 뒤에도 화면 내부에 이전 문서의 텍스트와 이벤트가 남아 있었다. Codex에 문서 비우기와 파일 교체 시 초기화 경로를 검토하도록 요청하였고, 검토 과정에서 남은 내용을 재현하였다. 제안된 공통 초기화 함수를 적용하여 상태 값·결과 행·근거·헤더·원문을 함께 제거하였다. 문서 비우기와 새 파일 읽기 실패 경로에 같은 처리를 적용하고, 재발 방지 시험 2개를 추가하였다. 두 시험은 수정 전에는 실패하고 수정 후에는 통과하였으며, 브라우저에서도 이전 문서의 텍스트가 남지 않았다.

모바일 결과 표의 가로 넘침

좁은 화면에서 결과 표가 나타나면 페이지 폭이 582px로 늘어나는 문제가 발생하였다. Codex에 첫 화면과 결과 화면의 폭을 비교해 넘침의 원인을 찾도록 요청하였다. Codex는 표와 바깥 배치의 최소 폭을 원인으로 좁히고, 페이지 폭을 화면에 맞추면서 표 내부만 가로 스크롤하도록 제안하였다. 이를 적용한 재시험에서 페이지 폭이 375px로 맞춰졌으며, 최신 화면에서도 390px 폭으로 결과와 주요 조작을 확인하였다.
