1. 식별한 문제와 개발 목표

공시팀은 제출 전 DSD의 오류를 체크리스트에 따라 수기로 최종 확인한다. 제출이 집중되는 시기에는 반복 점검의 업무 부담이 과중해지고, 누락이나 재검토로 공시 일정이 지연될 위험이 있다.

반복 확인이 가능한 항목을 먼저 점검하고 오류 위치를 원문과 연결해, 담당자가 확인할 부분을 빠르게 찾는 것을 목표로 했다.

주요 기능구현 내용
DSD 읽기파일 선택과 끌어놓기로 문서를 불러온다.
서식별 점검감사·연결감사·분기·반기 검토보고서에 맞는 규칙을 적용한다.
결과 탐색상태별 필터와 검색으로 확인할 항목을 찾는다.
원문 확인항목별 근거와 문서 내 해당 위치를 함께 보여 준다.
검토·내보내기확인 표시를 남기고 CSV 또는 Excel로 결과를 저장한다.

2. 파일 선택과 점검 시작

감사인 기준을 확인한 뒤 DSD 파일을 선택하거나 화면에 끌어놓으면 점검이 시작된다.

사용 순서

  1. 감사인 명칭·식별값·주소·대표자 기준을 확인한다.
  2. 첨부 ZIP을 풀고 점검할 DSD 파일을 선택한다.
  3. 결과에서 오류 후보와 확인할 항목을 찾는다.
  4. 원문 근거를 검토하고 결과를 내려받는다.

3. 점검 결과와 검토

58개 출력 항목을 상태별로 모아 보여 주고, 검색과 필터로 필요한 결과를 좁힐 수 있다.

검토한 항목에는 ‘직접 확인’을 표시할 수 있다. 결과 파일에는 항목, 판정, 원문 근거와 확인 기록이 함께 포함된다.

5. AI 활용과 문제 해결

기존 DSD 읽기·점검 모듈을 바탕으로 독립 웹 화면을 구성했다. AI 코딩 도구를 활용해 파일 선택, 결과 탐색, 원문 연결과 내보내기를 구현하고, 실행 중 발견한 문제를 수정했다.

① 원문 근거 창의 닫기 버튼이 사라지는 문제

문제 원문 위치로 이동할 때 화면 전체가 스크롤되면서 제목과 닫기 버튼이 화면 밖으로 밀렸다.

AI 활용과 수정 원문 패널 내부에서만 스크롤하도록 수정 방향을 구체화했다. AI가 제안한 내부 스크롤 방식으로 바꾸고, 창을 열 때 상단 위치를 초기화했다.

결과 원문 위치로 이동한 뒤에도 제목과 닫기 버튼이 유지됐다.

② 문서를 비운 뒤에도 이전 내용이 남는 문제

문제 결과 화면을 숨겨도 내부 화면 요소에 이전 문서의 텍스트와 이벤트가 남아 있었다.

AI 활용과 수정 파일 교체·초기화 경로를 함께 확인하고, 상태 값과 결과 행·근거·헤더·원문을 공통 함수에서 제거하도록 수정했다.

결과 문서 비우기와 새 파일 읽기 실패 시 이전 내용이 남지 않았다. 재발 방지 시험 2개를 추가했다.

③ 모바일에서 결과 표가 화면을 밀어내는 문제

문제 좁은 화면에서 결과 표가 나타나면 페이지 폭이 582px로 늘어났다.

AI 활용과 수정 표와 바깥 배치의 최소 폭을 확인하고, 페이지는 화면 폭에 맞추되 표 내부만 가로 스크롤하도록 수정했다.

결과 기존 재시험에서 페이지 폭이 375px로 맞춰졌고, 최신 화면에서도 390px 폭으로 결과와 주요 조작을 확인했다.
